- 패스워드 → 패스키로 향해가는 이유
    1. 로그인의 간소화
        - 패스워드 입력 대신 생체인식/PIN의 사용자가 관리할 필요 없는 로그인 방식
        - 동기화 : 계정이 같으면 다른 기기로도 공유 가능
    2. 매우 안전
        - 피싱 방지 : 피싱 사이트는 도메인이 다르므로 아예 작동하지 않음
        - 서버에 패스워드 등 인증 정보가 남지 않음

- 패스키 인증 단계
    - 이전에 서버와 클라이언트가 공개키/개인키 쌍 생성
    1. 서버가 challenge 전송
    2. 내 기기에서 지문/PIN 등으로 인증
        - 인증 시 개인키로 challenge에 전자서명
    3. 서버가 전자서명을 내 공개키로 확인
    4. 로그인

- 기존 비대칭키 방식과의 차별점
    1. 개인키에 아이디 정보 포함, 별도 입력 필요 x
    2. 클라우드 서비스와 연동, 키 파일 복사x
    3. 도메인 귀속(피싱 차단)
    4. 패스키만의 보안
    - 키 생성 단계에 os가 관여하여 격리된 하드웨어 보안 구역에 생성, 추출 불가
    - 클라우드 동기화시 키는 종단간 암호화되어 관리자도 볼 수 없음

- 동기화 흐름
    1. 격리된 물리적 칩셋에 패스키 보관
    2. os가 개인키와 기기 고유의 암호(PIN 등)을 결합해 암호화
    3. 클라우드로 전송
    4. 새 기기에서 로그인 시 암호화된 개인키를 다운로드
    5. 이전 기기 방식으로 복호화
    6. 개인키 평문이 즉시 새 기기의 격리 구간으로 이동되어 저장

- 핵심 기술
    
    FIDO2(Fast Identiy Online) : 비밀번호를 사용하지 않는 인증 표준 협회, 규약
    
    - FIDO는 usb 방식, 2에서 어플/브라우저에 직접 적용
    
    WebAuth : API, 사이트와 브라우저, 운영체제 사이의 인터페이스
    
    **`navigator.credentials.create`**
    
    client-side 자바스크립트 코드에서 호출 시 브라우저에 인증 요청
    
    - 인증자 : 개인키 보관 중인 물리 하드웨어
    - 클라이언트 : 인증 요청을 받는 브라우저와 운영체제
    - 의존 당사자 : 로그인 시도 받는 서버

개인적으로 궁금했던 점

- 메모리 주소로 접근 불가, 물리적 주소가 달라 차단됨
- 하드웨어만의 로직이 있어서 운영체제를 제어한다고 해도 거부 당함
- 보안칩 자체가 강력하고 독립적인 기능을 함
