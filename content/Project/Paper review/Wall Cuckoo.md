Abstract : 사용자 요청에 대한 빠른 응답이 중요하기 때문에 인-메모리 데이터베이스를 사용, 쿠쿠 해싱(cuckoo hashing) -> 버킷화 쿠쿠 해싱(bucketized cuckoo hashing)까지 개선하였으나 여전히 오버헤드로 인한 효율 하락 문제가 있다. 본 논문에서는 월 쿠쿠(wall cuckoo)를 사용해 버킷 내부 데이터를 사용된 해시 함수에 따라 분리하여 슬롯 접근 횟수의 감소를 기대한다.


1. 서론
	- In-memory DB : 응답 속도의 향상을 위해 메모리에 데이터를 저장하여 디스크의 캐시처럼 사용, key-value 구조이며 다양한 클라우드 서비스 제공자들이 사용
		- linked list 기반의 hash table을 사용해 충돌 처리, least recently used로 캐시 관리
		- 삽입이 빠르나 탐색이 느리며, 캐시 미스 시 체인 전체를 탐색해야 해 비효율적이다.
	- Cuckoo hasing : 두 개의 해시 함수를 이용하며, x가 들어갈 자리 h_1(x)에 y가 있다면 y를 h_1(y) or h_2(y)으로 이동 그 자리에 다른 데이터가 있다면 같은 방식으로 반복
		- worst case에도 O(1)만큼의 시간이 걸림
		- 메모리 사용률이 조금만 높아져도 밀어내기 연쇄 반응이 심해져, 메모리를 절반까지만 사용 가능
	- Bucketized cuckoo hasing : 데이터 저장 단위(slot)을 여러개 묶어 버킷 형태로 만들어 메모리 사용률 개선(밀어내기 횟수 감소시킴)
		- 빈 슬롯에 대한 위치 정보가 없어 데이터 삽입 시 추가 연산이 필요함
		- 쿠쿠 해싱보다 탐색이 느림
	- Wall cuckoo : 버킷에 월이라는 분리 지점을 추가해 월 변수 기준으로 서로 다른 해시 함수로 삽입된 데이터들을 분리 및 관리
		- 삽입/탐색 시 필요한 메모리 접근 횟수를 줄인다.
		- 메모리 사용률이 높을 때도 성능 유지 가능

2. Wall Cuckoo 고속 삽입 및 탐색 방법

		- 탐색 : 월의 앞 또는 뒷부분만 확인하므로 슬롯 접근 횟수가 줄어든다.

4. 결론
	월 쿠쿠는 메모리 사용률이 95%일 때 BCH보다 positive 탐색에서 36%, negative 탐색에서 46% 감소한 슬롯 접근 횟수를 보였다. 또한 정렬 쿠쿠에 비해서도 positive 탐색 29.5%, negative 탐색 20% 감소한 접근 횟수를 보였다. 수행 시간에서도 10% 가량 성능 향상을 보였다. 비교적 적은 추가 메모리로 삽입과 탐색에서 성능 향상을얻을 수 있었으며, 멀티 스레딩 환경에서도 메모리 접근 시 lock 시간을 줄이는데 활용할 수 있다. 


리뷰 소감 :
학과 교수님 중 한 분이 참여하신 논문이기도 하고, 최근 운영체제 강의에서 메모리 접근 횟수를 줄여야 시간을 포함한 성능이 좋아진다고 배웠기 때문에 관련 주제에 흥미를 느꼈다. on-chip 메모리에 관해서는 배웠었는데 여기서는 메모리가 디스크의 캐시 역할을 관점이라 새로웠다. 또한 데이터 구조 시간에 들었던 hash table의 실제 사용을 볼 수 있어서 신기했다. 다만 거의 10년 전 논문이기 때문에 지금은 메모리 효율이 얼마나 더 증가했으며, 최신 기술은 어떤 것을 사용하는 지 궁금해졌다.
